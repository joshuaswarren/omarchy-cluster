# Strata vs omarchy-cluster (2026-10-07)

[Strata](https://github.com/Niko1221/Strata) (Niko1221) is a C++/CUDA/HIP inference engine for one model
family — [Qwen3.8-Flash-Next](https://huggingface.co/Qwen/Qwen3.8-Flash-Next), a 125-billion-parameter
MoE with hybrid linear attention — plus a Python server with an OpenAI- and Anthropic-compatible API and
a one-click installer for Windows and Linux. MIT license. Created 2026-09-24; v0.1.40.2 released
2026-10-07 (near-daily releases); 16.6k stars, 1.4k forks, 277 open issues; a
[paper PDF](https://github.com/Niko1221/Strata/blob/main/docs/paper/Strata-Paper.pdf) ships in the repo.
This note asks whether it can run on our nodes, whether omarchy-cluster can use it, and whether its
ideas would speed up our measured bottlenecks.

## What it supports

| Backend | Floor | Notes |
| --- | --- | --- |
| CUDA | compute capability 7.5 (RTX 20+) | experimental second engine for Pascal/Volta (sm_60/70) via CUDA 12; nothing below sm_60 ([OLDER_GPUS.md](https://github.com/Niko1221/Strata/blob/main/docs/OLDER_GPUS.md)) |
| HIP | RDNA1 (gfx1010) and newer, MI50 (gfx906) | RDNA3/4 via setup, older cards hand-built ([AMD_HIP.md](https://github.com/Niko1221/Strata/blob/main/docs/AMD_HIP.md)) |
| SYCL | Intel Arc | experimental, separate `sycl/` tree ([INTEL_ARC.md](https://github.com/Niko1221/Strata/blob/main/docs/INTEL_ARC.md)) |

- No Vulkan backend, no Metal backend, no CPU-only mode: a supported GPU is required, and the CPU is
  only the fallback pool for MoE experts that no card holds (`AGENTS.md`, [DETAILS.md](https://github.com/Niko1221/Strata/blob/main/docs/DETAILS.md)).
- Windows or Linux, x86_64 packaging (`setup.py` targets x86_64 throughout; no aarch64 build).
- Models: Qwen3.8-Flash-Next and its Coder, Swift 1.5 and Unsloth-quant variants only, in a
  GGUF-derived pack format (`tools/iq_pack.py`, `experts.bin`).

## How it splits work — always inside one PC

- **MoE expert tiering.** All experts live in pinned host RAM or an mmap'd file; the GPU holds the
  hottest ones ranked by a measured router profile; adaptive swaps follow the conversation; the router
  of layer *n+1* is applied early to prefetch the pages of its likely experts
  (`--resident-experts`, `--resident-budget-gib`, `STRATA_LOOKAHEAD`).
- **Multi-GPU layer split.** Contiguous layer ranges per card, one hand-off per speculative verify
  window (a few hundred KB over PCIe) instead of per layer; no NVLink or P2P needed
  ([MULTI_GPU.md](https://github.com/Niko1221/Strata/blob/main/docs/MULTI_GPU.md)). Measured on an
  RTX 5080 + RTX 3090: prompt throughput +18-20%, decode on par with the faster card alone.
- **Speculative decoding.** The model's own MTP draft layer proposes a window of tokens that all
  devices verify together; `--pipeline-windows 2` lets the first card start the next window while the
  last card verifies this one (measured +16% mean decode).
- **KV tiering.** KV streaming (`--kv-resident`) and q4_0 / k8v4 quantized KV trade context memory
  against expert-cache slots.
- **No network transport.** `src/` has no socket or RPC layer; the layer split assumes every card
  shares one host's pinned RAM over PCIe. There is no cross-machine mode of any kind.

## Verdict against our nodes

| Node (as named in our README) | Strata requirement | Result |
| --- | --- | --- |
| Mac Studio on macOS (Metal) | no macOS, no Metal backend | cannot run |
| M2 Max and M1 Max on Omarchy Linux (Vulkan/Honeykrisp, aarch64) | no Vulkan backend, no aarch64 packaging | cannot run |
| 13-inch M1 (CPU host) | no CPU-only mode | cannot run |
| x86 laptop, Quadro M1200 (CUDA sm_50) | CUDA floor is sm_75 (experimental path starts at sm_60) | cannot run |

**Not applicable as an engine.** Zero nodes qualify, and the only model it runs is Qwen3.8-Flash-Next —
not the GLM models the cluster exists to split. There is also no MLX connection: different runtime, no
MLX backend, GGUF-derived packs rather than safetensors. omarchy-cluster could bind to it at the
orchestration level exactly like any OpenAI-compatible upstream, but only for a supported GPU on an
x86 box, and only for that model — which no current node satisfies.

## What it would take to make it compatible

Three separate projects, each large:

1. **Run it on our hardware:** write a Vulkan (or Metal) backend. The IQ dequant kernels, GDN
   attention, sampling and tensor-core paths are CUDA/HIP-specific; this is a kernel-layer rewrite,
   not a port. The x86_64 assumptions in setup would also need lifting for aarch64.
2. **Run our models on it:** implement the GLM-5.3/GLM-5.3-Flash architecture and a pack converter;
   `tools/iq_pack.py` is Qwen-specific. The speculative pipeline depends on a model-specific MTP draft
   layer, which GLM support would also need.
3. **Borrow ideas without the code:** nothing to build to read their docs; the borrowable parts are
   design patterns, listed below.

## Would its ideas speed up our bottlenecks?

Our measured state: GLM-5.3 across five machines at a median 0.39 tok/s warm, GLM-5.3-Flash on four
Macs at 1.36-1.54 tok/s, RPC protocol cost 3.4-4.7 ms per token per hop
([receipts/2026-10-07-rpc-hop-cost](../../receipts/2026-10-07-rpc-hop-cost/README.md)), the host's
layers paging from disk, and slow Vulkan IQ kernels.

- **Amortize hops with verify windows (ESTIMATE).** Strata's layer split crosses each card once per
  speculative window, not once per layer; acceptance measured 2.65-2.88 tokens per window in their
  docs. The equivalent here needs llama.cpp to draft and verify across RPC devices, which it does not
  do today (draft-model decoding is local-only). If it ever did, the per-token hop cost would drop by
  roughly the acceptance factor — but hops are not the binding constraint: at 0.39 tok/s a token takes
  ~2.5 s, against roughly 14-19 ms of hop overhead in the measured 4-5-hop chains.
- **Profile-ranked residency for the paging host (direction applicable, win unmeasured).** Strata's
  answer to "experts do not fit" is exactly our host's problem: keep the router-profile-ranked hottest
  experts in locked RAM, read the rest from disk, prefetch the next layer's likely pages. llama.cpp
  already mmaps layers but has no router-profile page ranking. Whether this helps must start with
  measuring the paging cost per layer
  ([receipts/2026-10-07-rpc-protocol-profile](../../receipts/2026-10-07-rpc-protocol-profile/README.md)
  marks it "paging not yet measured").
- **Slow Vulkan IQ kernels: no lift.** Strata has no Vulkan path. Its headline speed comes from CUDA/HIP
  tensor-core kernels and from model choice — the GDN linear attention is O(1) per token by design, so
  much of the speed is the model, not the engine.
- **Heterogeneous memory across machines: explicitly out of scope for Strata.** It is one PC only. The
  network-split niche omarchy-cluster occupies is untouched — like exo, it is not a competitor here.

If the fleet ever gains one supported GPU box (any RTX 20+ or RDNA2+ card with 12 GB or more), Strata
plus Qwen3.8-Flash-Next would serve that box alone at 40-90 tok/s decode by their measured tables — a
single-node LiteLLM upstream beside the cluster, and a model-swap decision rather than a cluster
feature.

## License and maturity

MIT (`LICENSE`) — no constraint on borrowing ideas or code. The project is two weeks old with
effectively one author and near-daily 0.1.x releases: expect churn, and treat its measured numbers as
their-rig numbers. Its docs and benchmark hygiene are unusually good (every claim carries a rig and a
date), which makes it a good reading source even where the code cannot run here.

## Actions

1. **Do not integrate.** No node can run it and it runs none of our models. Re-check if it ships a
   Vulkan/Metal backend or a second model family.
2. **Attack the measured ceiling first:** the host paging its residency design mirrors — measure paging
   per layer, then pin resident layers or move them to a node with headroom. Larger lever than hop
   amortization at today's 0.39 tok/s (estimate).
3. **Watch for distributed speculation in llama.cpp.** If RPC draft/verify lands, or GLM gains an MTP
   draft, revisit amortizing hops into multi-token windows (estimate: hop cost divided by the
   acceptance factor, ~2.6x at Strata's measured acceptance).
