# CL08: choose joint-request phase separation

CL08 asks for a request to use one device for prompt evaluation and another for token generation, while preserving the gateway’s `/generate` contract and measuring the handoff. The merged CL08 change implements that path as `--engine joint`: prefill, save the llama-server slot, transfer KV, restore it, then decode. See [PR #133](https://github.com/joshuaswarren/omarchy-cluster/pull/133), `omarchy_cluster/joint_engine.py`, `tests/test_joint_engine.py`, and the joint flags and telemetry contract in `docs/cli.md`.

There are two distinct implementation halves. **KV transfer** connects those phases across hosts: the prefill llama-server saves slot state; `transport_kv` copies it locally or moves it through the node agent’s scoped `/v1/kv` endpoint; the decode server restores the slot. PR #133 supplies an injectable `transport` argument to `joint_generate`, loopback fake-server tests for prefill/save/restore/decode ordering, and a remote-path test that substitutes the agent pull. This is already a concrete module boundary and test seam. The sources document serialized access to one shared slot and require matching model and context; the transport boundary isolates the network hop from phase orchestration.

**Sharding above 32 GB** is a different capacity concern, not a phase handoff. The existing llama.cpp path already maps model layers to RPC endpoints and tensor splits (`docs/placement.md`, `omarchy_cluster/llamacpp_engine.py`). The placement receipt `receipts/2026-10-15-swa-kv-reservation/README.md` measures a 173.34 GB, five-shard model and shows KV sizing changing from 8.32 GB to 3.79 GB at 32,768 tokens and from 33.29 GB to 10.23 GB at 131,072 tokens. That evidence describes memory reservation and placement; it does not identify a missing joint-request phase boundary.

**Choose KV transfer as the implementation half.** It directly delivers CL08’s prompt/decode phase split, while >32 GB sharding is an independent placement/capacity track with existing planner and RPC seams. Implementing the transfer half avoids coupling a new request lifecycle to planner changes. Its risks are concrete and bounded: mismatched model/context or slot use can invalidate restore, and transport failures must stop decode. The existing tests already exercise those negative paths and serialize requests around shared slot state.

**Test seam:** inject the KV transport at `joint_generate(..., transport=...)` and run the phase chain against the two loopback fake llama-servers in `tests/test_joint_engine.py`. Assert the observable order (prefill completion → save → injected transfer → restore → decode), transferred bytes, and that a transport failure returns an error without decoding. This tests phase separation at the boundary between orchestration and storage/network movement without hardware or a live cluster.
